# Відповіді до лабораторної роботи № 4

1. REST адресує ресурси за URI та використовує стандартні дії HTTP. RPC адресує операції за ім’ям методу, наприклад `RegisterDevice`.
2. Безпечний метод призначений для читання. Ідемпотентний має той самий очікуваний ефект на сервері при повторенні однакового запиту. `GET` безпечний та ідемпотентний. `PUT` і `DELETE` ідемпотентні. Загальний `POST` може створити новий запис під час кожного виклику. Коди повторних запитів можуть відрізнятися, як `204` і `404` після видалення.
3. Chi надає суброутери, групові middleware й параметри маршрутів, залишаючись сумісним з `http.Handler`. Radix Tree стискає спільні префікси шляхів і використовує їх для пошуку маршруту. У Go 1.22 `ServeMux` також підтримує методи й параметри в шаблонах, а в Chi зручно групувати маршрути й middleware.
4. Карта потребує синхронізації, коли запис і читання можливі одночасно. `RWMutex` дає кільком читачам працювати паралельно й забезпечує виключний доступ для запису. `Mutex` також може забезпечити коректність, але серіалізує читання.
5. Коли запит виконано й клієнту достатньо статусу та заголовків. За HTTP відповідь із кодом `204` завершується після заголовків, без тіла.
6. Middleware виконує свої дії до виклику наступного обробника або після його повернення. Щоб зупинити ланцюжок, middleware може сформувати відповідь самостійно.
7. Відкладена функція викликає `recover()` у тій самій горутині. Вона логує стек і формує `500`, якщо сервер ще може відправити новий статус. Інші запити обробляються далі.
8. Це механізм браузера для міждоменного доступу. Браузер звіряє заголовки `Access-Control-Allow-*` і для певних запитів спочатку надсилає `OPTIONS`. За відсутності дозволу він блокує доступ скрипту до відповіді або припиняє запит після preflight.
